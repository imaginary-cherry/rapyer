# Requirements: rapyer — Configurable TTL Cascade

**Defined:** 2026-07-06
**Core Value:** Give Redis users a genuine relational-ORM experience — setting a parent's TTL must atomically and server-side re-arm every cascade-enabled referenced child to its own `Meta.ttl` (a cascading refresh), at set-time.

> "User" below means a **developer using rapyer** to define models.

## v1 Requirements

Requirements for this milestone. Each maps to a roadmap phase.

### Configuration (CFG)

- [x] **CFG-01**: User can opt a `ForeignKey` relationship into TTL cascade by declaring `Annotated[Reference[T], CascadeTTL(...)]` on the field, consistent with the existing `Key[...]`/`Index[...]` DSL
- [x] **CFG-02**: User can set a global default cascade policy at `init_rapyer(...)`; it is **disabled by default** so existing projects are unaffected
- [x] **CFG-03**: A per-field `CascadeTTL` overrides the global default, with documented precedence (field > global > off)
- [x] **CFG-04**: `CascadeTTL` exposes `enabled` (opt-out), `depth` (traversal depth), and `mode` (a `TTLCascadeMode` enum), with sensible defaults

### Cascade Behavior (CASC)

- [ ] **CASC-01**: Setting or refreshing a parent's TTL re-arms every cascade-enabled referenced child to its **own `Meta.ttl`** (a cascading refresh, not propagation of the parent's TTL value), including each child's own special-field keys; the root aggregate is always fully refreshed to its own `Meta.ttl`. See 02-CONTEXT.md D-04/D-07.
- [ ] **CASC-02**: Both cascade **discovery** (FK-graph traversal) and **apply** (the EXPIRE fan-out) run inside one registered server-side Lua script as a single atomic operation — no partial/interleaved application and no discovery→apply TOCTOU (retires the earlier Option-B split). See 02-CONTEXT.md D-01.
- [x] **CASC-03**: Traversal follows the `ForeignKey` graph to the configured `depth` (default keeps behavior bounded and predictable)
- [x] **CASC-04**: Traversal is cycle-safe (visited-set) and bounded by a max-depth guard; shared children and self-references terminate cleanly
- [ ] **CASC-05**: The `mode` surface collapses to a single-member `TTLCascadeMode.EXTEND` enum, kept purely as the EXT-01 extension seam — with per-child own-TTL there is no parent-vs-child comparison, so `OVERWRITE`/`IF_UNSET` and the `GT`/`NX` flags are **not** implemented this milestone; apply uses a plain relative `EXPIRE` correct on all Redis 6.0–7.4. See 02-CONTEXT.md D-05/D-06.
- [ ] **CASC-07**: A cascade-reachable target declaring `Meta.ttl is None` raises at `init_rapyer()` (fail-fast, after FK-target resolution) rather than silently no-op'ing at runtime. See 02-CONTEXT.md D-08.
- [ ] **CASC-06**: Cascade rides inside the triggering write's existing transaction/atomic boundary (`ensure_pipeline`), never re-implementing root/special-field resolution (uses `resolve_root_model` + existing special-field iteration)

### Compatibility (COMPAT)

- [ ] **COMPAT-01**: With no `CascadeTTL` configured anywhere, existing `Meta.ttl` / `refresh_ttl` behavior and the `refresh_ttl`-excludes-`DELETE` rule are unchanged (regression-verified)
- [x] **COMPAT-02**: Existing `ForeignKey` declaration and `afetch`/`aget` usage are unaffected

### Extensibility (EXT)

- [x] **EXT-01**: The cascade backbone is shaped so delete-cascade and save-cascade can plug in later without redesign — traversal shared, apply/action swapped; only TTL implemented now

### Testing & Docs (TEST)

- [ ] **TEST-01**: Cross-model TTL cascade is covered by **real-Redis integration tests** and by unit tests under fakeredis, explicitly confirming fakeredis JSON-in-Lua (`JSON.GET` + `cjson.decode`) parity with real Redis; no `EXPIRE GT/NX/XX` version-matrix concern remains (relative `EXPIRE` only, per D-05)
- [ ] **TEST-02**: The `CascadeTTL` API and semantics are documented (docs site + docstrings) alongside the existing foreign-key docs

Deferred to future milestones. Tracked, not in this roadmap.

### Cascade Framework (FRAME)

- **FRAME-01**: Delete cascade (ON DELETE CASCADE / SET NULL / RESTRICT) on the shared backbone
- **FRAME-02**: Save cascade (persist related children atomically on parent save)

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Expiry-event cascade | Impossible by construction — an expired parent's JSON is gone, so children are unreachable; cascade is set-time only |
| Per-edge custom TTL *values* | Each child is refreshed to its own `Meta.ttl` (D-04); a cascade edge that sets some *other* explicit TTL value is a separate concern, not this milestone |
| Reverse cascade (child → parent) | Forward-direction only for v1; unclear semantics, high complexity |
| Delete / save cascade (implementation) | Backbone is designed for them, but only TTL is implemented this milestone |
| Redis Cluster cross-node cascade | rapyer keys carry no hash tags → `CROSSSLOT`; physically impossible on Cluster |
| Referential-integrity coupling (FK existence checks at write) | Separate feature; not part of TTL cascade |
| Table-like registry + bulk ops | Desired later; out of this milestone |

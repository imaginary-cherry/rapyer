## v1.3.5 Configurable TTL Cascade (Shipped: 2026-07-20)

- Pure-Python `CascadeTTL`/`CascadeSpec`/`TTLCascadeMode` config surface plus `RedisConfig.cascade_ttl` + `init_rapyer(cascade_ttl=...)` global-default wiring, verified by 22 new unit tests.
- Additive `_cascade_ttl_fields` classification detects `Annotated[Reference[T], CascadeTTL(...)]` markers across all three D-06 FK shapes (direct, collection, nested submodel) without touching a single line of the existing fragile FK/SF classification loop.
- `CascadePlanner.atraverse()` — an async BFS FK-graph walker covering all three D-06 shapes (direct FK, collection-of-FK, nested-submodel FK), with a per-subtree depth budget (field > global > off) and a visited-set as the real cycle-termination guarantee — verified by 40 unit tests, no Lua/EXPIRE yet.

- 1. [Rule 1 - Bug] `test_every_model_gets_exactly_one_entry_even_a_plain_leaf` asserted a stale `ttl: None` for `CascadeAuthor`
- Proves the registered `cascade_ttl_apply` Lua script end-to-end: a fakeredis unit suite invokes the real `EVALSHA`-registered script across every D-06 FK shape (scalar/shape-1, collection-of-FK/shape-2, nested-submodel/shape-3), diamond dedup, self-reference cycle safety, the special-field-child key-refresh gap flagged in Phase 1's HUMAN-UAT, and WR-02's accepted order-dependent semantics; a real-Redis Stack confirmatory suite then proves dual-backend parity for the one scenario where fakeredis diverges (shape-2 collection traversal) and that the script survives a `SCRIPT FLUSH` via the existing NOSCRIPT self-heal path.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Denial of Service | `push_edges` SF-container member decode (`library.lua`) | mitigate | Wrap every member decode in `pcall(cjson.decode, raw_member)`; on failure, skip that member instead of letting the error propagate and abort the whole atomic FCALL — mirrors the existing `read_reference_paths` swallow-on-decode-failure pattern. Proven by Task 3 Test F. |
| T-02-02 | Tampering (data integrity) | `push_edges` SF-container `push_child` call (`library.lua`) | mitigate | Guard with `type(target_key) == 'string'` before calling `push_child`, exactly as the existing scalar-FK branch already does — a decoded JSON number/object/table is never treated as a Redis key argument. Proven by Task 3 Test F. |
| T-02-03 | Information Disclosure / Elevation of Privilege | Redis Function execution scope | accept | No new attack surface — the Function already runs entirely server-side inside an already-atomic, already-trusted execution context; this phase adds a read of application-owned data, not a new entry point |
